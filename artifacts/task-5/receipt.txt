DEFECT FOUND AND FIXED IN THIS PASS
  `ld: warning: ignoring duplicate libraries: 'libterminal_proto.a'`
  Cause: rm_terminal listed terminal_proto and terminal_logging explicitly
  even though both already arrive transitively through terminal_presentation
  (-> terminal_domain -> terminal_proto, all PUBLIC), so the archive landed on
  the link line twice. Fixed by linking only the direct dependency:
    target_link_libraries(rm_terminal PRIVATE terminal_presentation
                          ${MOSQUITTO_LIBRARY} Qt6::Widgets)
  Transitive linkage confirmed intact:
    otool -L build/debug/rm_terminal | grep -iE 'mosquitto|QtWidgets|QtCore'
  The build is now warning-free in both configurations.

RECORD GRAMMAR
  ts=<ISO8601 UTC with ms> level=<debug|info|warning|error> event=<token> k=v ...
  Both harnesses assert every emitted line against that grammar, not just the
  lines they care about. lifecycle-run.log asserts it once across all 15 records;
  events-run.log asserts it once per scenario, so 4 hits:
    grep -cE 'matches the (record )?grammar' lifecycle-run.log events-run.log
  Timestamps are asserted monotonically ordered across 5 restarts, and restarts
  append rather than truncate.

EXIT-CODE CONTRACT (unchanged from tasks 1-4, re-asserted here)
  0 success
  2 malformed command-line arguments; stderr bounded (<=256 bytes), no banner
  3 transport start failure
  4 configuration or log-destination failure
  A MISSING config file is deliberately NOT an error: defaults apply and the
  process starts, so a fresh checkout runs with no config file. A config file
  that EXISTS but does not parse is always a loud exit 4.

CONFIGURATION
  Keys and defaults are documented in BUILD.md and rm_terminal.conf.sample:
    mqtt_host=127.0.0.1  mqtt_port=3333  udp_port=3334
    stale_window_ms=500  log_level=info  log_destination=rm_terminal.log
  Defaults mirror the 2026 local-simulation baseline so the native terminal and
  the Python simulator agree with no config file present. No source edit is
  required to change any of them, which is the task-5 acceptance criterion.

STALE-DATA SEMANTICS
  A field aging into Stale logs once per TRANSITION, not once per snapshot. The
  GUI inspects on a 250ms timer, so per-snapshot logging would bury every other
  event during a stall. `domain_state` asserts: NeverReceived is not reported as
  stale, a fresh field is not reported, the transition logs exactly one record
  naming the group and stale count, repeated inspections of an unchanged stale
  set stay silent, and a group going stale later logs a new transition.

PACKET-LOSS SAMPLING
  packet_loss is capped at one record per second. Under 10% loss over a 6-second
  window the harness observed 6 records and asserts <= 7, proving the cap holds;
  without it a lossy 20fps stream would emit thousands of records per second.

CONCURRENCY
  The file mutex and the sink mutex are separate. The composition-root sink calls
  back into StructuredLog::write and QMutex is not recursive, so holding the file
  mutex across the sink invocation would self-deadlock. config_test covers the
  sink path, double-open, double-close, and post-close writes.

READ-ONLY BOUNDARY
  Re-audited after this task's edits. No CAN/UART write, no MQTT CustomControl
  or CommonCommand publish, no gimbal/chassis/launcher/auto-aim logic.
  The logger has NO network sink: its only destination is a local file, which is
  why `--log` takes a path and not a host. Operator banners go to stderr via
  qInfo/qCritical. Verify with:
    grep -rniE 'mosquitto_publish|can_send|uart_write' cpp/          # no hits
    grep -rniE 'QTcpSocket|QUdpSocket|QNetworkAccessManager' cpp/logging.cpp
  The only matches for control-shaped names in cpp/ are inbound read-only
  telemetry field names and one test asserting the CustomControl topic is
  REJECTED (cpp/intake_test.cpp).
