## 一、这个仓库到底干了什么

用大白话说：做了一块「第二块屏幕」。

比赛时操作手眼睛盯着官方选手端操控机器人，官方选手端已经有大图传画面了。但官方选手端看不到对方的血量和经济，而且一旦对方飞镖击中我方基地，官方选手端会黑屏。这两个空档就是这个终端的价值所在：

- 平时：用来看官方选手端**不给你看**的信息（敌方四台车的血量、雷达看到的位置、双方总伤害和控制度、堡垒激活进度）。所以图传画面只需要一个小窗口。
- 黑屏时：自动把图传切成全屏，让操作手还能继续开车。

这个「自动切换」是整个项目里最有工程含量的一块，不是加个按钮让人手动切——比赛中人根本没空手动切，而且切换时机必须跟着飞镖命中走，不能跟着任何人的偏好走。2027 协议没有「致盲」字段，终端收到对方飞镖命中（Event 9）后按规则手册 5.7.3 自己算遮挡多久。

终端按席位工作：重装 1 号、步兵 3/4 号、指挥手 6 号（蓝方 +100），开机选定。三种席位的界面不同，重装多一块装配面板，指挥手多飞镖、哨兵面板和地图标记。

### 已经做出来的能力

**界面（已完成）**
- 开机选席位页；状态条左端显示席位，三种席位三种布局（步兵、重装、指挥手），1280x760 到 1920x1080 都有布局测试
- 顶栏：比分、倒计时、轮次、基地血条、基地防御状态（防御增益/护甲展开）、控制度对比条、前哨站徽标
- 我方/敌方花名册：每方 4 台（1 重装、3/4 步兵、7 哨兵），头像、编号、兵种、血条、血量百分比，我方带剩余发弹量
- 战术地图：自机坐标来自服务器，其他车来自雷达，标注雷达特殊标识；收到的地图标记；指挥手还能看到哨兵规划路径、在地图上点击发标记
- 战场事件时间轴：Event 翻成中文（击杀、前哨站被击毁、阵地易手、飞镖命中、装配结果……），时间是比赛倒计时
- 战场数据分析：堡垒激活进度、我方经济、双方总伤害、双方击杀（Event 1 本机累计）、能量机关、四个阵地和推进计时、控制度、后勤系数
- 重装装配面板；指挥手飞镖、哨兵面板：发送限频 10Hz，断线不发不排队，不可撤回的操作要按住 1 秒，2 秒没回执提示「未确认」
- 步兵、重装的「本车指令」面板（在我方花名册下面）：赛前选性能体系（只有步兵）；比赛中兑换发弹量、远程兑换发弹量、远程兑换血量、开能量机关（只有步兵，按住 1 秒）
- 复活照官方选手端：阵亡时弹出复活框，点「金币复活」花钱满血复活；读条满后点「免费复活」或按 Y。替换掉原来的「已阵亡 等待复活」弹窗（只在步兵、重装席位）
- 键鼠控制：状态条上的「键鼠控制」开关或 F9，终端接管键盘鼠标，按 75Hz 发 `KeyboardMouseControl`；Esc/F9、窗口失焦、断线都会退出，退出时补发一帧「全部松开」；阵亡时自动暂停、放开鼠标，复活后自动继续
- 图传窗口：带丢帧/断流统计
- 双模式布局：Info（地图为主 + 图传缩略图）／Video（图传全屏），自动切换带防抖

**数据链路（已完成）**
- 2027 官方自定义终端协议（通信协议 V1.0.0，2026-10-29，2.2.1–2.2.32 全部消息）

- 数据新鲜度三态模型：新鲜／过期／从未收到。每个字段独立判定，一个字段过期不会让旁边好的字段也显示成过期

**图传（已完成）**
- UDP 分片重组，能处理乱序、重复、丢包
- H.265 硬解码
- FPS、丢帧、断流统计

**模拟器（已完成）**

- 模拟 BO3 局分、基地/前哨站血量、经济、双阵地组合控制度、堡垒激活和护甲、飞镖与遮挡、装配、哨兵姿态、能量机关
- 按席位发 2027 官方消息（「己方/对方」相对席位），回应终端发来的装配、飞镖、哨兵、地图标记、兑换/远程兑换/复活、性能体系、能量机关指令，并统计终端发来的键鼠帧
- 席位每次启动手动选（红 1/3/4/6、蓝 101/103/104/106），选定后本局锁定；脚本/CI 用 `RM_SELF_ID` 直接指定

## 二、这个项目是怎么做出来的

技术路线是 **C++17 / Qt6 / QML**，CMake 构建。

分层大致是这样，从下往上：

```
Python 模拟器  ──MQTT/ProtoBuf──>  解码  ──>  领域状态模型  ──>  界面
Python 图传端  ──UDP 分片──────>  重组  ──>  H.265 解码   ──>  图传窗口
```

几个关键的技术决定，以及为什么这么定：

**界面从 QWidget 转向 QML。** 最开始整个界面是纯 QWidget 手画的，做出来是白纸黑字的表格，被否掉了。QWidget 的质感上限低，要做出渐变、发光、圆角、精细边框这类效果非常费劲。最后的方案是混合：整体骨架还是 QWidget（布局稳定、和 C++ 数据层接得顺），但顶栏和花名册这两块最讲究质感的换成 QML（`QQuickWidget` 加载 `qrc:/qml/TopBar.qml`），颜色间距字号全部收进一个 `Theme.qml` 单例，避免各文件颜色漂移。

**时间全部用单调时钟。** 进程里每一个时间戳都来自 `monotonic_now()`，一个共享的 `steady_clock` 原点。绝对不用墙上时钟——如果比赛中系统对时（NTP）把时间往回拨，用墙上时钟的话进程会直接崩；往前跳的话，模式退出的等待窗口会在没有观察到任何数据的情况下「凭空走完」。这条有两个测试守着，其中一个会在 `cpp/` 里再次出现 `currentMSecsSinceEpoch` 时直接让构建失败。

**配置外置。** 端口、过期窗口、防抖时长、日志等级全在 `rm_terminal.conf` 里，改了不用重新编译。配置文件缺失是允许的（用默认值），但文件存在却写错了会**大声失败**，退出码 4 并指出是哪个键、哪一行——不会静默忽略。

**证据化验收。** `--screenshot` 出图，`--dump-layout` 同一时刻导出布局 JSON。因为截图只能靠肉眼判断，JSON 才能让「Info 模式下地图占主要区域」这种断言被脚本检查。JSON 里只有布局不含比赛数据，否则每次跑数值都变，diff 全是噪音。

工作方式上，是按模块推进的：每完成一块，跑构建、跑测试、截图，给用户验收，通过了再进下一块。界面这块反复了十几轮。

## 三、遇到的挫折和问题，怎么解决的

这部分写实，不美化。

### 界面被否了十几轮

第一晚做出来的界面是白纸黑字的表格，用户的原话是「你一晚上改出来的 ui 就这？太垃圾了吧」。后面还有反复的「还是很丑」「怎么会这么丑」「注册表比顶部的拉跨 100 倍」。

真正解决问题的转折点有三个：

1. **用户提供了参考对象。** 官方选手端的 PDF，以及开源项目 `ClearWei/RM26_Client`。光靠描述「要好看」是做不出来的，有了具体参照才有方向。
2. **用户直接把开源仓库克隆到本地**（`/Users/zy/RM26_Client`），并说「你去看看他们是怎么绘制 ui 的，你照搬就一定能让我满意」。之后地图素材、前哨站徽标、边框线条风格都直接取自那里的 `resources/`，不再自己造丑东西。
3. **换技术栈。** 认清 QWidget 手画到不了想要的质感，顶栏先用 QML 试点，效果被认可后推广。

这里的教训很直接：审美类需求没有参考物就是在猜，猜十轮不如给一张图。

### 曾想把界面外包给子任务，被否

中途提出让别的执行单元去做界面，用户否掉了：「你自己不能做吗，为啥非要拍别人做，我感觉别人做的又慢效果又不好」。后面界面全部自己做。

### 满屏「过期」字样

界面上每台车都常驻显示「(过期)」。查下去发现是过期窗口设成了 500ms，而 `RobotPosition` 是 1Hz 发布——窗口比发布间隔本身还短，位置数据刚到就被判过期。改成 2200ms（必须容得下最慢字段的两个发布周期）。

这个 bug 的真正危害不是难看，是**这个标记彻底失去了意义**：如果所有东西永远显示过期，那真正断流时你也看不出来。配置注释里现在写明了这条约束。

### 界面上一堆「无数据」，以为是代码 bug

蓝方没有基地血量、红方 4 号 5 号车是灰色的、比分显示 416:304 这种不像比赛的数字。查出来全是同一类原因：**模拟器没发布这些字段**，界面显示「无」是正确行为。解决办法是补模拟器（`feat(sim): publish field objectives, team names and full-field HP`），不是改界面。

比分那个是把某个数值错当比分显示了，真实比赛不会出现三位数比分。

### 敌我阵营写死了

界面里红方是我方、蓝方是敌方写死在代码里。用户指出：实际赛场我们不一定是红方还是蓝方。改成从数据里的 `faction` 字段判定，花名册按「我方/敌方」而不是「红方/蓝方」组织。

### 一堆细碎但必须改的视觉问题

图标发光、图标太大又没有编号、地图只占中间一条上下大片黑、地图有黑缝、R 标太小又挡住校名、前哨站徽标位置不对、绿条中间多一条线、亮绿亮黄太刺眼、花名册有时胖有时瘦、图传「ONLINE」字样难看、锁定光晕出现在普通底座上。这些逐条改掉了，大部分是对着开源项目的画法改。

### 端口 3333 残留进程导致测试随机失败

`mode_regression_e2e` 这个 62 秒的端到端测试会随机失败。原因是上次跑的模拟器没退干净：**两个模拟器在同一个 broker 上，每个 topic 的观测速率翻倍**，而且第二条致盲时间线的相位不同，会制造出终端根本没产生过的模式切换。

解决办法有两层：脚本启动前检测是否已有 `match_server.py` 在发布，有就拒绝运行；`run.sh` 里先 `pkill` 清残留。另外 `ps aux | grep [m]atch_server` 现在是排查任何速率异常的第一步。

### 构建依赖遗漏

`domain_test.cpp` 和 `decoder.cpp` 缺 include，地图那次提交漏了初始依赖。都是常规修复，但暴露出一个问题：本地增量构建能过不代表干净克隆能过。后来验证方式改成从远端重新 clone 再独立构建 + 跑测试。

### 共享工作树导致改动混杂

多个主题的修改混在一起，最后是拆成 8 个按主题的提交推上去的（协议、领域层、界面、模拟器、素材、配置修复各自独立）。

### PDF 读取

用户要求参照官方选手端 PDF，页数多截图截不过来，坚持「你必须读到 PDF」。这块花了额外的功夫。

## 四、这个项目的优势和亮点

**1. 需求是从操作手真实使用场景推出来的，不是照搬官方。**
最有代表性的是图传窗口的大小。照搬官方选手端就会给图传一块大画面，但那是重复建设——比赛中操作手本来就盯着官方选手端。真正的需求是「官方选手端黑屏时的备份」和「官方选手端看不到的敌方数据」。所以布局优先级是按辅助操作手的方便程度排的，图传平时只占一个小窗口。这个判断是用户提出的，是整个界面布局的立足点。

**2. 数据新鲜度是逐字段独立的。**
不是「整个连接好/坏」这种粗粒度判断。每个字段自己判过期，一个字段过期不影响旁边的字段显示。缺失和「值恰好是 0」是能区分开的——`has_x() == false` 是没收到，`has_x() == true && x == 0.0` 是真的在原点。这个区别很要紧：混淆的话，没有位置的车会被画在场地角上。

**3. 自动模式切换的工程细节到位。**
致盲断言立刻进全屏（晚一点丢画面比早一点进更糟，所以进入没有延迟），解除要连续 3 秒才退出（否则信号在阈值附近抖动会让整个布局每秒翻好几次），退出窗口期间重新断言会取消并重新计时，数据过期时**保持**全屏而不是掉回去、且过期期间的时间不计入退出，但过期超过 15 秒会强制回到 Info 并记 `BlindSignalLost`——避免发布端死掉把终端永久钉在全屏。模式切换时解码器常驻不重启，`decoded_frames` 持续累加。

这些都不是「能跑就行」的实现，每条都对应一个具体的失效场景。

**4. 测试是有意义的测试。**
25 个测试里包含一个 62 秒的真实端到端回归：起 broker、起模拟器、起图传、跑终端，然后断言整个过程恰好产生两次模式切换、时机符合致盲窗口加防抖时长，输出实际对预期的对照表。单元测试全绿的状态机，喂错时钟或错的新鲜度照样会抖——只有端到端能证明接起来是对的。

**5. 可复现性做进了设计。**
时刻表模式确定性、布局 JSON 逐字节稳定、配置错误大声失败并指明行号、日志每条一行可 grep。

**6. 日志区分了原因。**
`ui_mode_switch` 带 `from`/`to`/`reason`/`blind_freshness`，而且只在真的切换时写，不是每 250ms 刷一条。「因为致盲数据死了所以保持全屏」和「真的被断言了」在日志里读起来是两回事。

### 中：图传缺真正的延迟指标

现在 UDP 分片头是 8 字节，只有帧 ID、分片序号、总长度，**没有发送端时间戳**。所以算不出真正的端到端延迟——只有 FPS、丢帧、断流。要做延迟就得改协议头加发送时间戳。码率（bitrate）和抖动（jitter）也还没有。

这三个词的意思：延迟是画面从摄像头到你眼前花的时间；码率是每秒传多少数据；抖动是每帧到达间隔的不稳定程度。比赛里延迟最要命，抖动会让画面一卡一卡。

### 已完成：录像和回放；还没有：复盘报告

实况默认录制原始 MQTT 消息和图传 UDP 包，`回放录像.command` 能按原速、变速、拖动回放。还没有的是自动生成复盘报告（控制度、血量、经济曲线和关键事件）。

## 六、需要注意的事

**协议已对齐 2027 V1.0.0，但还没和官方服务器联调。** 上面「已完成：换成 2027 官方协议」那一节列了联调时要核对的几处。

**席位选错，服务器会把这台终端当成别的车。** 登录名就是席位车号，自检页会核对，选错时标红。

**2027 协议迁移后的验证都在 Ubuntu 上做。** macOS 上还没重新跑过。

**键鼠控制要在 X11 下用。** Ubuntu 默认是 Wayland，Wayland 不让程序把光标拉回窗口中心，鼠标移到屏幕边就转不动了。正式用键鼠控制时用 `QT_QPA_PLATFORM=xcb` 启动终端；macOS 不受影响。

**测试视频只是占位素材。** `sim/assets/sim_feed.h265` 是一段 1280x720 的 HEVC 场景，不是真实比赛画面，只用来验证解码和图传链路通不通。

**不要同时跑两个模拟器。** 每个 topic 的速率会翻倍，还会制造假的模式切换。速率看起来不对时，第一件事是 `ps aux | grep [m]atch_server`。

**过期窗口不能小于最慢字段的两个发布周期。** `RobotPosition` 是 1Hz，所以 `stale_window_ms` 不能设到 1000 以下，否则过期标记会永久点亮从而失去意义。

**`--force-mode`、`--screenshot`、`--dump-layout` 是调试工具，不是操作手功能。** 故意没有任何快捷键或按钮能改模式——比赛中模式必须跟着致盲信号走。强制模式不会伪造日志，`reason` 会记成 `ForcedByCli`。

**Python 跑模拟器要加 `-u`。** 不加的话输出重定向到文件时会块缓冲，进程被信号中断时致盲时间线那几行就丢了。

## 七、不懂计算机怎么用（macOS）

以下命令全部在「终端」App 里，一行一行复制粘贴，每行按回车。所有命令都在仓库目录下执行。

### 第一步：装依赖（只做一次）

先装 Homebrew 包管理器（如果没装过），然后：

```sh
brew install cmake qt mosquitto protobuf
```

- `cmake` 构建工具
- `qt` 界面框架
- `mosquitto` MQTT 消息服务器（模拟赛事引擎的通信中枢）
- `protobuf` 数据编码

### 第二步：进入仓库目录

```sh
cd /Users/zy/RMGF/terminal
```

如果是新克隆的：

```sh
git clone git@github.com:zy-2006-08/RM_Terminal_27.git
cd RM_Terminal_27
```

### 第三步：准备 Python 环境（只做一次）

模拟器要用 Python，跟终端本体是分开的：

```sh
python3 -m venv .venv
.venv/bin/pip install protobuf paho-mqtt
```

### 第四步：编译终端（改了代码才需要重做）

```sh
cmake -S . -B build/macos
cmake --build build/macos
```

结束后会得到 `build/macos/rm_terminal`，这就是终端本体。

### 第五步：确认没有残留进程

上次没关干净的话会出各种怪问题，先清一遍：

```sh
pkill -f 'sim.match_server'; pkill -f 'sim.video_sender'; pkill -f 'mosquitto -p 3333'
```

（没有残留时会提示找不到进程，这是正常的。）

### 第六步：启动

双击 `启动.command`（或在终端运行 `./启动.command`）。

每次启动都必须先手动选择席位（红 1/3/4/6、蓝 101/103/104/106；1 重装、3/4 步兵、6 指挥手），没有默认值，选定后本局锁定。脚本随后拉起 mosquitto、模拟赛事服务器、模拟图传、终端界面和控制面板；关掉这个窗口即全部停止。直接运行 `rm_terminal` 时它会自己弹出选席位页，也可以用 `--seat 103` 跳过。

验收或 CI 可以用 `RM_SELF_ID=103 ./启动.command` 跳过交互。需要分开调各进程时见 `run.sh`。

想试丢包效果就把 `run.sh` 里的 `--loss 0` 改成 `0.02`（2% 丢包）。

### 界面上看什么

- **最上面一条**：左边是席位（如「红方 3 号 · 步兵」），右边是四个链路灯、REC、自检、战术提醒
- **顶栏**：红方基地血条和防御状态，中间比分、倒计时和控制度对比条，右边蓝方，两侧是前哨站
- **花名册**：每方 4 台车（1 重装、3/4 步兵、7 哨兵），头像、血条、血量百分比，我方带剩余发弹量。**敌方血量是官方选手端看不到的**
- **中间战术地图**：场地俯视图，自机位置来自服务器，其他车来自雷达；收到的地图标记
- **战场事件**：赛事事件按时间倒序，分级配色
- **战场数据分析**：堡垒、我方经济、双方总伤害和击杀、能量机关、四个阵地
- **图传**：小窗口的第一视角画面
- **重装**多一块「装配」；**指挥手**多「飞镖」「哨兵」和地图下的标记工具条

显示 `--` 表示这个数据还没收到；带「(过期)」表示数据太久没更新。

### 手动控制比赛

```sh
# 裁判流程：准备/自检/倒计时/继续/暂停/复位到赛外
.venv/bin/python sim/match_control.py prep
.venv/bin/python sim/match_control.py check
.venv/bin/python sim/match_control.py countdown
.venv/bin/python sim/match_control.py resume
.venv/bin/python sim/match_control.py pause
.venv/bin/python sim/match_control.py reset
.venv/bin/python sim/match_control.py seek 34

# 阵地：0/1 前哨区，2/3 基地区；状态 1 红临时/2 红完全/3 蓝临时/4 蓝完全
.venv/bin/python sim/match_control.py zone 2 2

# 持续激活：连发临时控制信号，维持临时控制不因 5 秒未激活而回退
.venv/bin/python sim/match_control.py hold 1 1 6

# 花金币兑换允许发弹量（17mm 10 发/10 币，42mm 1 发/10 币，全队上限 1000/100 发）
.venv/bin/python sim/match_control.py buy 17 100

# 对锁定目标打 10 发 17mm（42mm 用 shoot 42 10）
.venv/bin/python sim/match_control.py shoot 17 10

# 重装安装模块化 42mm 发射机构（仅重装：600 HP / Q0=300 / 冷却 100/s）
.venv/bin/python sim/match_control.py module

# 飞镖：阵营 1 红 / 2 蓝；目标 1 前哨站、2-5 基地目标
.venv/bin/python sim/match_control.py dart-open 1
.venv/bin/python sim/match_control.py dart 1 1
```

飞镖只在比赛内 30s、240s 起的各 30s 开闸窗口可用，开闸 7 秒后进入 30 秒发射窗口，每局 4 枚、冷却 15 秒。官方流程是 3 分钟准备 + 15 秒自检 + 5 秒倒计时，模拟器默认自动流转；联调时用 `RM_PREP_SEC=1 RM_CHECK_SEC=1 RM_COUNTDOWN_SEC=1` 缩短，`RM_HOLD=1` 则停在赛外等按钮/命令推进。`RM_MATCH_SEC=60` 可缩短单局。基地被击毁或一局时间耗尽后进入结算，结算结束回到准备阶段，按 BO3 继续（先到 2 局分结束整场）。

阵地控制度按组合结算：同时控制两个前哨阵地 +1/秒，同时控制两个基地阵地 +3/秒（临时控制计入）。阵地转化按规则表 5-21：连续激活对方完全控制的阵地 5 秒取得临时控制；临时控制方 5 秒不再激活即退回原方完全控制（`hold` 持续下发可维持激活，面板点「持续激活 6s」）；临时控制转完全控制必须击毁该阵地的前哨站，持续激活不会升级；基地阵地只有初始拥有方能完全控制；毁坏的前哨站随后按 5.6.1 重建 500 HP。己方完全控制己方前哨阵地时基地获得 100% 防御增益（飞镖等特殊伤害绕过）。规则不允许的阵地状态会被拒绝。

### 自动切全屏怎么看

在控制面板选「红方 + 基地随机移动目标」点「中镖」（席位是红方时），模拟器发出 Event 9，终端算出遮挡 10 秒，界面自动切成图传全屏；10 秒后再等 3 秒防抖切回。也可以命令行（直接注入一次命中，不走开闸流程）：

### 改配置

```sh
cp rm_terminal.conf.sample rm_terminal.conf
```

然后用文本编辑器打开 `rm_terminal.conf` 改。常用的几项：

| 键 | 默认 | 意思 |
| --- | --- | --- |
| `mqtt_port` | `3333` | 消息服务器端口 |
| `udp_port` | `3334` | 图传接收端口 |
| `stale_window_ms` | `2200` | 多久没更新算过期（**不要低于 1000**） |
| `mode_exit_hysteresis_ms` | `3000` | 遮挡结束后等多久才退出全屏 |
| `log_level` | `info` | 日志详细程度 |
| `map_enabled` | `true` | 是否画战术地图 |
| `self_robot_id` | （不写） | 席位；不写就每次开机弹选席位页 |
| `display_fullscreen` | `false` | 开机全屏（重装、指挥手接官方 1080p 显示器时打开） |

改完直接重新运行，不用重新编译。写错了程序会立刻报错并告诉你是哪一行。

### 出问题怎么办

**界面打开但全是 `--`**：模拟赛事服务器（窗口 2）没起来，或者端口不对。看窗口 2 有没有报错。

**图传是黑的**：图传发送端（窗口 3）没起来。另外解码需要几秒钟，等一下。

**满屏「过期」**：`stale_window_ms` 被改小了，调回 2200。

**数值跳动异常、速率看起来翻倍**：有两个模拟器在跑。执行 `ps aux | grep [m]atch_server` 查，然后 `pkill` 清掉。

**`ModuleNotFoundError: google`**：Python 环境没装好，重做第三步。注意要用 `.venv/bin/python` 而不是直接 `python3`。

**端到端测试随机失败**：残留进程占着 3333 端口。先 `pkill` 再跑。

**看日志**：程序运行记录在 `rm_terminal.log`，每条一行。想看模式切换就搜 `ui_mode_switch`。
