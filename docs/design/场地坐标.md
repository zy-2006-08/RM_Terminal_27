# 场地坐标

终端用来判断「敌人从哪条路进来」「站在哪个增益点上」的场地数据。坐标一律是协议坐标：米，原点在红方补给区那一角，x 沿场地长边 0–28，y 沿短边 0–15，红方在 x 小的一边（`cpp/field_map.h`）。

## 从哪来的

- 官方场地模型 `RMUC2027_V1.0.0.stp`（Creo 导出，零件名带中文；624MB，不进 git，本机放在 `docs/rules/`）。`python3 scripts/stp_landmarks.py docs/rules/RMUC2027_V1.0.0.stp > build/stp_landmarks.json` 读出每个零件的范围（顶点外包盒），几秒钟。模型换版本时重跑一遍，对照下表改 `cpp/field_zones.cpp`。
- 模型坐标换协议坐标：x = (14000 − X) / 1000，y = (9124.5 − Y) / 1000（模型是毫米、红方在 +X）。
- 规则手册图 5-23（增益点分布）和小地图底图（就是这个模型的俯视图）对照着描了中央高地那条走道和基地外面那圈六边形。

## 终端怎么用

- **敌方进入我方半场**（横幅）：雷达看到敌车从它那半场过了中线（离中线 0.3 米以上才算），写「敌方 3 号步兵从隧道进入我方半场」。
  - 有雷达情报时看 0x0A04 里我方这边的跨越点：中央高地上方 → 「中央高地坡」，公路上方 → 「起伏路段」，隧道那 9 个 → 「隧道」。
  - 没有就按过中线那一刻的 y：1.94–13.07 是中央高地坡，两头是隧道。起伏路段在各自半场里面（红方的在 x 5.2–7.2、y 0.2–2.3），不在中线上，只能靠雷达情报认。
  - 雷达跟丢过（过中线前最后一次看到它超过 3 秒）就只写「敌方 3 号步兵进入我方半场」。同一台 15 秒内只报一次。
- **按位置推增益**（标签带「约」，没有雷达情报的敌车和没有服务器 Buff 的队友才推）：
  - 基地增益点、制高点增益点：防御 50%。中央高地增益点：防御 25%。
  - 自己的堡垒增益点：防御 50%（自己的前哨阵地不在自己手里时才生效）。
  - 补给区：回血 10%，重装无敌。装配区里的重装：可能无敌（看不出在不在装配）。
  - 站在对方堡垒上、对方堡垒正被激活、对方基地护甲还没展开：易伤 100%。
- **偷堡垒的是哪一台**：我方堡垒被激活时，站在我方堡垒增益点上的敌车写进横幅和「下一步」的回防卡：「敌方 3 号步兵在激活我方堡垒 · 易伤100%」。雷达没看到就还是「那台」。

## 误差和没核对的

- 外包盒对斜着放的零件偏大，描的多边形边上差二三十厘米；雷达定位自己也有这么大的误差。
- 「站在增益点上」不等于激活了：要车上的场地交互模块检测到卡（规则 5.6.4.1），所以都写「约」。
- 中线两头到底是不是隧道、起伏路段的确切边界，要在真场地或 26 引擎上走一遍核对。
