# 用 2026 赛事引擎测试 2027 自定义终端：宝宝教程

2027 赛事引擎裁判端要到 2027 年 4 月才发布。在那之前，可以用 2026 的整套软件（裁判端 + 官方选手端），加上队里的车、图传、雷达和自定义控制器来测终端。两年的传输方式一样，大部分消息定义也一样；少数字段 26 和 27 含义不同，见附录 A，测到时别当成 bug。

标了 **【未验证】** 的地方是根据文件和资料推断的，第一次做的时候顺手确认，然后把结论改回这份文档。

---

## 0. 能测什么、测不了什么

能测：

- 网络、MQTT 连接、席位核对、断线重连
- 裁判数据：比赛流程、经济、基地和前哨站血量、事件、飞镖命中后自动全屏、能量机关、判罚
- 真车数据：血量、热量、发弹量、模块状态、受伤统计、阵亡和复活
- 终端发的指令：兑换、复活、性能体系、能量机关、飞镖、哨兵、地图标记
- 图传（UDP 3334）
- 键鼠控制
- 自定义控制器 → CustomControl → 车上 0x0311；车上 0x0310 → CustomByteBlock → 自定义控制器
- 雷达（RadarInfoToClient）
- 有哨兵的话：哨兵指令和哨兵路径（RobotPathPlanInfo）

测不了：

| 内容 | 原因 |
| --- | --- |
| 重装装配（AssemblyCommand、TechCoreMotionStateSync） | 26 里装配是工程（2 号）的功能，终端没有 2 号席位 |
| 控制度、阵地、机制 3–6、事件 5–8/14/16、模块化 42mm | 27 新机制，26 引擎不发；继续用项目自带模拟器测 |
| 31–60 字节的 CustomControl | 26 最多 30 字节。小机械臂每帧 30 字节，不受影响 |

## 注意事项（开始前必看）

### 注意事项 1：车上程序要先改成 27 的做法，否则 8.6 测不了

27 删掉了自定义控制器专用的 0x0302 和 0x0309，控制器的数据改成经终端转发。车上程序要做到两件事：

- **收 0x0311**：控制器每帧 30 字节，终端用 CustomControl 发出去，车上收到的是 0x0311。2026 的车上程序收的是 0x0302，不改就收不到。
- **发 0x0310**：机械臂反馈（6 个关节角 + 1 个标志，共 25 字节）放在 0x0310 的最前面，每包不超过 300 字节、每秒不超过 50 包。终端从里面取出这 25 字节，写回控制器。

测之前让电控确认车上程序已经有这两部分。还是 2026 的程序，8.6 的第 39、40、42 项就跳过，别的项目照常测。第 38、41 项只看终端和控制器之间通不通，不用等车上程序，只有控制器的板子也能测。

### 注意事项 2：测键鼠时车要架空、不装弹

- 车轮垫起来离地，发射机构不装弹；旁边站一个人，随时能给车断电。
- 8.5 第 35 项要在按住 W 的时候拔掉终端网线，看车停不停、多久停。终端退出键鼠控制时会补发一帧「全部松开」，但网线拔了，这一帧发不出去，车停不停取决于选手端怎么处理。
- 车一直不停，说明选手端会一直转发最后一帧按键：比赛中终端网线一松，车就会一直往前开。**这个结果比赛前必须知道**，和电控一起定好处理办法，再决定比赛用不用终端控车。

## 检查顺序：先查上游，再查终端

网络、裁判数据、图传是一层压一层的：IP 不对就 ping 不通，ping 不通终端就收不到数据；选手端自己的画面不正常，终端也不会有好画面。按下面的顺序一步一步查，前一步没过，先别去查后一步。

| 顺序 | 查什么 | 怎么算过 | 在哪一节 | 第一次上车时卡在这里的情况 |
| --- | --- | --- | --- | --- |
| 1 | 每台电脑的固定 IP | 终端电脑 192.168.12.2；选手端电脑接终端的那个网口 192.168.12.1；掩码都是 255.255.255.0，网关空着 | 3.2–3.4 | 选手端接终端的网口还是「自动获取」，自己给自己分了一个 169.254.x.x 的地址。改成固定 192.168.12.1 就好了 |
| 2 | 终端能不能 ping 通选手端 | 终端电脑 `ping -c 4 192.168.12.1` 4 个包都有回复；`nc -vz 192.168.12.1 3333` 能连上 | 3.6、6 | ping 不通，原因就是第 1 步那个 |
| 3 | 裁判数据 | 启动终端后，比赛状态和裁判端同步、一致：「裁判」灯绿，自检页「席位正确」，开赛后倒计时在走、经济在涨 | 7、8.1 | 比赛没开始时，终端显示「每秒约 0 条」，日志里一堆 `ignored malformed ... GameStatus`。原因是服务器发的局号是 0、时间是 -1，终端当成无效数据丢掉了。开赛后就正常，不是 bug |
| 4 | 选手端自己的图传 | 选手端上有画面，而且流畅 | 5、5.1 | 见 5.1 的三种问题 |
| 5 | 终端的图传 | 8.4 第 30 项抓包能看到 192.168.12.1 发来的 3334 包；终端图传有画面 | 7、8.4 | 3334 一个包都没有，是选手端还没往终端发。关掉选手端的设置面板，不行就重启选手端，之后就开始发了（具体是哪一步起的作用没确认） |
| 6 | 自定义控制器 | 「控制器」灯绿，鼠标停在灯上写「每秒 25 帧」 | 8.6 | 板子里还是云台程序，串口 3 用 460800 给小电脑发自瞄数据，终端收不到 0x0302。换成控制器程序后，又是 J18 的线序接错了，见 8.6「控制器板子怎么接」 |

## 1. 三台电脑怎么分

| 电脑 | 跑什么 | 系统 | 接什么 |
| --- | --- | --- | --- |
| 裁判端电脑 | 2026 赛事引擎（裁判端 + 服务器） | Windows | 网线接路由器，固定 192.168.1.2；要能上外网 |
| 选手端电脑 | 2026 官方选手端 | Windows | 网口 1 网线接路由器（自动获取 IP）；USB-C 接图传接收端；网口 2 固定 192.168.12.1，网线直连终端电脑 |
| 终端电脑 | 2027 自定义终端 | Linux 小电脑 | 网线接选手端电脑，固定 192.168.12.2；USB 转串口接自定义控制器；USB 接键盘鼠标 |

有两台 Windows 就照这张表接。只有一台 Windows 看 1.1。

**为什么裁判端和选手端最好分开放**：放在同一台上没人验证过，有三个风险。

1. 官方部署是分开的：裁判端电脑固定 192.168.1.2，选手端电脑从路由器自动拿地址。放在一台上，选手端和服务器是同一个 IP，不知道服务器认不认。
2. 两个程序都要开网络端口，可能撞端口。
3. 选手端要解 1080p60 的图传再转给终端，会和裁判端抢 CPU 和显卡。终端上看到卡顿、丢帧时，分不清是终端的问题还是那台电脑忙不过来。

### 1.1 只有一台 Windows 怎么办

按顺序试，前一个不行再试下一个。

#### 方案 1：一台 Windows 同时跑裁判端和选手端（不用花钱，先试这个）

这台 Windows 同时当裁判端电脑和选手端电脑：

- 网口 1：网线接路由器，固定 192.168.1.2（照 3.2 做）
- 网口 2（USB 网卡）：固定 192.168.12.1，网线直连终端电脑（照 3.3 第 2 条做）
- USB-C：接图传接收端
- 第 3 节其余照做，只有一处不同：**3.3 第 1 条跳过**，网口 1 保持 192.168.1.2，不要改成自动获取
- 先开裁判端（第 4 节），再开选手端（第 5 节）；选手端问服务器地址时填 192.168.1.2

正式测之前先做三项检查，对应上面三个风险：

| 检查 | 怎么做 | 通过 |
| --- | --- | --- |
| 同一个 IP 服务器认不认 | 做完第 5 节 | 选手端能登录 R3，有比分和倒计时，用这台电脑的键盘能开车 |
| 撞不撞端口 | 开选手端之前和之后，各在命令提示符里运行一次 `netstat -ano \| findstr LISTENING`；找到 3333 那行最后的 PID，运行 `tasklist /FI "PID eq 这个PID"` | 3333 属于选手端的进程；开了选手端之后，裁判端没有出现「未连接服务器」 |
| 电脑忙不忙得过来 | 开着图传打 5 分钟比赛，同时开着任务管理器 | 终端图传约 60 帧，丢帧接近 0；CPU 和 GPU 占用都不到 80% |

- 前两项有一项不过：换方案 2 或方案 3。
- 只有第三项不过：其余功能照常测，只是 8.4 第 28 项（帧率、丢帧）的结果不算数，以后分开放再测一次。可以先把裁判端窗口最小化、插上电源、电源模式调成「最佳性能」再试一次。

没有 USB 网卡时【未验证】：给网口 1 再加一个 IP。IPv4 属性 → 高级 → IP 地址 → 添加 `192.168.12.1`，掩码 `255.255.255.0`，原来的 192.168.1.2 留着。终端电脑也插到路由器 LAN 口，照 3.4 设 192.168.12.2。两台电脑接在同一台路由器上，两个网段可以直接互通。

#### 方案 2：MacBook 跑裁判端

裁判端只要一根网线接路由器、能上外网，不接 USB 设备，也不处理图传，最适合挪到别的机器上。选手端留在这台 Windows 上，因为它要接图传接收端，还要解码图传。

先看 MacBook 是哪种芯片：左上角苹果菜单 → 关于本机。

- 写「Intel」：用 Boot Camp 装 Windows，开机选 Windows，它就是一台普通的 Windows 电脑，当裁判端电脑最稳。
- 写「Apple M…」：只能用虚拟机，比如 Parallels Desktop 或 VMware Fusion，装 Windows 11 ARM 版。【未验证】裁判端是 x64 程序，在 ARM 版 Windows 里靠系统转译运行，能不能打开、卡不卡要试。虚拟机网络选「桥接」；Mac 用 USB 网卡插网线接路由器；虚拟机里的 Windows 照 3.2 设 192.168.1.2、关防火墙。

#### 方案 3：借一台 Windows 笔记本当裁判端电脑

队友的就行。要求只有三条：能插网线（或者用 USB 网卡）、能上外网、能登录 DJI 账号。

## 3. 第一步：接线、配 IP

### 3.1 路由器

用手机或电脑登录路由器后台：

1. LAN 口 IP（路由器自己的地址）改成 `192.168.1.1`，子网掩码 `255.255.255.0`
2. 打开 DHCP
3. 2.4G Wi-Fi：名字随便起，密码 `12345678`，加密 WPA2（引擎《联网操作手册》规定的，车和雷达的裁判系统连这个）
4. WAN 口接能上网的网线

> 路由器**不能**用 192.168.12.x 网段，否则会和终端的地址冲突。

### 3.2 裁判端电脑

1. 网线接路由器 LAN 口
2. 「控制面板 → 网络和 Internet → 网络连接」→ 右键网口 → 属性 → Internet 协议版本 4 → 属性
   - IP `192.168.1.2`，掩码 `255.255.255.0`，网关 `192.168.1.1`，DNS `223.5.5.5`
3. 关闭 Windows 防火墙（引擎手册要求的）：「控制面板 → Windows Defender 防火墙 → 启用或关闭」，三种网络都选关闭

PowerShell（管理员）也可以，接口名改成你电脑上显示的：

```powershell
New-NetIPAddress -InterfaceAlias "以太网" -IPAddress 192.168.1.2 -PrefixLength 24 -DefaultGateway 192.168.1.1
```

### 3.3 选手端电脑

1. 网口 1：网线接路由器 LAN 口，保持「自动获得 IP 地址」（默认就是）
2. 网口 2（或 USB 网卡）：网线接终端电脑。拔插一下 USB 网卡，在「网络连接」里消失又出现的那个就是它
   - IP `192.168.12.1`，掩码 `255.255.255.0`，**网关和 DNS 都留空**
3. 图传接收端用 USB-C 接上，按你们 2026 年用选手端的做法装好驱动
4. 防火墙：第一次打开选手端时弹窗点「允许」；终端还是连不上就把防火墙关掉

```powershell
New-NetIPAddress -InterfaceAlias "以太网 2" -IPAddress 192.168.12.1 -PrefixLength 24
```

### 3.4 终端电脑（Linux）

```sh
# 看网口叫什么，找 TYPE=ethernet 的那行，比如 enp1s0
nmcli device

# 建一个只给终端用的连接，固定 192.168.12.2，不设网关（Wi-Fi 上网不受影响）
sudo nmcli con add type ethernet ifname enp1s0 con-name rm-terminal \
    ipv4.method manual ipv4.addresses 192.168.12.2/24 ipv6.method disabled
sudo nmcli con up rm-terminal

# 确认
ip addr show enp1s0        # 要看到 inet 192.168.12.2/24
```

测完想恢复：`sudo nmcli con down rm-terminal`。

### 3.5 车和雷达

上电，按你们 2026 年的做法让裁判系统连上路由器的 Wi-Fi。

### 3.6 检查：都能 ping 通才往下走

| 在哪台上 | 命令 | 通过 |
| --- | --- | --- |
| 终端电脑 | `ping -c 4 192.168.12.1` | 4 个包都有回复 |
| 选手端电脑 | `ping 192.168.1.2` | 4 个包都有回复 |

不通：先看防火墙是不是关了，再看 IP 是不是填在了正确的网口上。

## 4. 第二步：启动裁判端（裁判端电脑）

1. 解压 `RoboMasterEngine 12.0.0.176_Student.7z`，双击 `RoboMasterEngine.exe`
2. 勾选「我已阅读联网操作手册」「我已阅读用户隐私协议」
3. 点「本地 IP 配置测试」和「外网连接测试」，**两个都要通过**（第一个检查有没有 192.168.1.2，第二个检查能不能上外网）
4. 用 DJI 会员账号登录（扫码 / 邮箱 / 手机号）
5. 点「开始使用」，服务器会自动启动；弹出防火墙就全部勾选允许
6. 赛制选 RMUC

**通过**：进入裁判端主界面，没有「未连接服务器」；车和雷达显示在线。

### 4.1 登录虚拟道具（基地、前哨站、能量机关等，不需要硬件）

在**裁判端电脑**上用浏览器打开（只能在服务器本机用）：

```
RoboMasterEngine_Data\StreamingAssets\RMServer\Server\Lua\VirtualDeviceOperationUI\VirtualDeviceOperationPanel.html
```

点「一键登录所有道具」：基地、前哨站、科技核心、雷达广播、飞镖发射站、能量机关都会虚拟上线。后面用它模拟飞镖命中、激活能量机关。

**通过**：面板底部没有报错，裁判端界面上基地和前哨站显示在线。

### 4.2 缺的车用虚拟机器人补

虚拟道具面板的「飞镖命中」要求先登录对面的「学生飞镖机器人」。不登录的话点了服务器不认：不扣血，也不发命中事件，终端自然不会切全屏。没有哨兵时测哨兵指令也要一台 7 号。引擎 `Config/gm_history.txt` 里有前人输过的 `-loginsturobot 1`、`-loginsturobot 102` 这类指令，是登录学生虚拟机器人用的。

## 6. 第四步：确认 3333 端口和 topic

**选手端电脑**（命令提示符）：

```bat
netstat -ano | findstr 3333
```

**通过**：有一行 `LISTENING`，地址是 `0.0.0.0:3333` 或 `192.168.12.1:3333`。

**终端电脑**：

```sh
nc -vz 192.168.12.1 3333
```

**通过**：显示 `succeeded` 或 `open`。

再看选手端发了哪些 topic（只打印 topic 名和长度，不打印乱码）：

```sh
# -i 3 表示以 3 号的身份连，和选手端登录的 R3 一致
mosquitto_sub -h 192.168.12.1 -p 3333 -i 3 -t '#' -F '%t %l'
```

比赛开始后，统计每个 topic 10 秒内来了多少条：

```sh
timeout 10 mosquitto_sub -h 192.168.12.1 -p 3333 -i 3 -t '#' -F '%t' | sort | uniq -c
```

**通过**：大概是这样（按协议的频率）：

| topic | 10 秒大约多少条 |
| --- | --- |
| GameStatus | 50（5Hz） |
| RobotDynamicStatus | 100（10Hz） |
| GlobalUnitStatus、GlobalLogisticsStatus、RobotStaticStatus、RobotModuleStatus、RobotPosition、RobotRespawnStatus、RobotInjuryStat、RuneStatusSync 等 | 10（1Hz） |
| Event、PenaltyInfo、Buff | 有事件才有 |

**把这份统计结果整段复制下来存好**，这是 26 引擎实际行为的第一手证据。

几种情况：

- `#` 什么都收不到：换成逐个订阅，`-t GameStatus -t GlobalUnitStatus -t RobotStaticStatus`，有的服务器不让订阅通配符
- 连不上，或者连上马上被断开：clientID 不对。clientID 就是选手端登录的那个号（登录 R3 就是 `-i 3`），号不一样服务器直接拒绝（8.9 第 51 项验证过）
- 3333 没打开：看选手端登录了没有、防火墙关了没有

> **测完一定要按 Ctrl+C 关掉 mosquitto_sub 再开终端**。同一个 clientID 只能连一个，后连上的会把先连的踢掉。

### 8.6 自定义控制器和 0x0310 / 0x0311（席位 3 或 1，按你们机械臂装在哪台车上）

> 第 39、40、42 项要车上程序先改成 27 的做法，见「注意事项」第 1 条；第 38、41 项不用等，只有控制器的板子也能测。
>
> 控制器只插在终端电脑上，**不要**同时插在选手端电脑上。26 的选手端自己也认自定义控制器，会变成两路数据。

#### 控制器板子怎么接

先确认两件事，再插到终端电脑上：

1. **板子里是控制器程序**：串口 3，115200，每秒发 25 帧 0x0302（每帧数据 30 字节），同时收终端写回来的 0x0309。板子里如果还是云台程序，串口 3 是用 460800 给小电脑发自瞄数据的，终端一帧 0x0302 都收不到。
2. **J18 的线序**（25 英雄云台板，3 针插座，中间是 2 脚）：TX 和 RX 要交叉接。

| J18 | 是什么 | 接串口板的 |
| --- | --- | --- |
| 1 脚 | RX3（PB11，板子收） | TXD |
| 2 脚（中间） | TX3（PB10，板子发） | RXD |
| 3 脚 | GND | GND |

第一次接线时，下面两种现象都遇到过，线序改对以后两个方向都通了：

| 现象 | 多半是 |
| --- | --- |
| 板子发给终端正常，终端发给板子一个字节都收不到 | 1 脚和 3 脚对调了：PB11 接到了串口板的 GND，一直被拉低 |
| 两个方向都不通 | TX 接了 TX、RX 接了 RX，或者插头没插到底 |

分不清哪边是 1 脚时，断电后用万用表蜂鸣档量 J18 两边的针，和板子 GND 通的是 3 脚。

配置里写 `controller_serial=auto`（见第 7 节），终端会自己找到串口板，换了串口板不用改配置。

已知问题：板子程序解 0x0309 时用的 CRC 算法不对（用了图传整包那种要取反的 CRC16），每一帧都被记成「CRC 错」。现在这段代码不按 CRC 丢帧，数据照样能收到；以后做力反馈、要丢掉坏帧之前，先改成和发 0x0302 时一样的 CRC16。
